# Backend architecture

Node 22+ · Express 5 · TypeScript (strict, ESM) · Prisma 7 (driver adapter `pg`) · PostgreSQL (local + Supabase) · Zod · Pino.

## Layout

```
prisma/
  schema.prisma                 data model (source of truth for tables)
  migrations/
    …_init/                     generated by Prisma from schema.prisma
    …_constraints_and_indexes/  hand-written: CHECKs, partial unique/indexes, RLS
src/
  config/env.ts                 zod-validated env; process exits on bad config
  lib/                          prisma client, logger, errors
  middleware/                   error envelope, (auth, rbac, validate – next)
  modules/<feature>/            routes → controller → service → (prisma)
  app.ts / server.ts            app factory / process entrypoint + graceful shutdown
```

Planned modules: `auth`, `users`, `customers`, `catalog` (products, variants, taxes), `plans`,
`quotation-templates`, `subscriptions`, `discounts`, `billing` (job + invoices), `payments`, `reports`.
Each module owns its routes, validation schemas and service; services never import another module's
routes. Cross-module calls go service → service.

## Key decisions

| Concern | Decision |
|---|---|
| Money | `NUMERIC(12,2)`, `Prisma.Decimal` in code, never `number`. Totals reconciled by a DB CHECK. |
| Double billing | Partial unique index `(subscriptionId, periodStart) WHERE status <> 'CANCELLED'`. Billing is idempotent by construction. |
| Billing job | Claim due subs with `SELECT … FOR UPDATE SKIP LOCKED`; create invoice + advance `nextBillingDate` + record discount redemption in **one transaction**. Safe to run on N workers. Tracked in `billing_runs`. |
| Invoice integrity | Invoices/lines are snapshots (price, tax rate, customer details). Later catalog edits never rewrite history. |
| Discount limits | `UPDATE discounts SET "usedCount"="usedCount"+1 WHERE id=$1 AND ("usageLimit" IS NULL OR "usedCount"<"usageLimit")`; CHECK constraint is the backstop. `UNIQUE(discountId, invoiceId)` = once per invoice. |
| Payments | Insert payment + bump `invoices.amountPaid` + flip to PAID in one tx, with `SELECT … FOR UPDATE` on the invoice. Overpayment blocked by CHECK. `idempotencyKey` makes retries safe. |
| Overdue | Derived, never stored: `status='CONFIRMED' AND dueDate < today` (served by partial index). |
| Numbering | `document_sequences` upsert-increment (`SUB-2026-000123`, `INV-2026-000456`), concurrency-safe. |
| Concurrency | `subscriptions.version` optimistic lock for edits/transitions; status changes write `subscription_status_history`. |
| Auth | argon2id passwords · 15 min JWT access token · rotating opaque refresh tokens (hashed, family reuse detection) · hashed single-use reset tokens · RBAC `ADMIN > STAFF > CUSTOMER`; customers are scoped to their own `customerId` in every query. |
| Reporting (<2 s) | Indexed aggregates over `invoices`/`payments`/`subscriptions`; keyset pagination; add materialized views only if measurements demand it. |
| Observability | Pino JSON logs with request ids and secret redaction, `/healthz` (liveness), `/readyz` (DB), audit log table. |
| DB safety | RLS enabled on all tables with no policies → Supabase's public PostgREST surface is denied; the API uses a direct Postgres role. |

## Database setup

Two URLs, because Supabase's transaction pooler (pgbouncer) cannot run DDL:

- `DATABASE_URL` – runtime. Supabase: pooler string, port **6543**, `?pgbouncer=true`.
- `DIRECT_URL` – `prisma migrate` only. Supabase: direct/session string, port **5432**.
- Locally both point at the same local Postgres.

```
npm run db:migrate:dev      # local: apply migrations (creates DB state)
npm run db:migrate:deploy   # Supabase / CI / prod: apply pending migrations, never prompts
npm run db:status
```

Schema changes: edit `schema.prisma` → `npm run db:migrate:dev -- --name <what>`; put any
CHECK/partial-index change in a new hand-written migration. Never edit an applied migration.
